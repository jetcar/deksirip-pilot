# DEKSIRIP 高层模型框架

> **翻译说明：** 本文由人工智能翻译，未经母语者审校。如遇歧义，以[英文版](model-framework-en.md)为准。发现误译请提交 [issue](https://github.com/jetcar/deksirip-pilot/issues)。

**状态：** Draft 0.1

本文先说明模型逻辑，再讨论技术选择。目标是让研究者在不了解软件架构的
情况下理解这项提议。

## 一、出发点：问题是什么

一个社会可能同时存在闲置资源和基本物资不足的人。资源不会自动与需求
连接起来，还需要准入规则、可用性信息、优先级决定、执行者以及结果验证。

DEKSIRIP 将此视为制度协调问题，而不仅是货币或生产能力不足的问题。

## 二、主要假设

如果让公共资源可见，把基本需求与支付能力分开，并把决定与可测量的后果
及独立审计连接起来，那么地方经济可能在没有单一中心安排每一项生产任务
的情况下，把剩余资源更好地用于需求和发展。

这是需要检验的假设，不是已经证明的普遍模型。

## 三、五个机制

### 3.1 基本保障

基本生活物资作为社区参与权提供，而不是只给有收入的人购买。能力边界和
短缺情况必须公开。

### 3.2 公共份额

公共资产产生的可分配收益，以等额或预先约定的方式返还居民。它提供安全
感和项目选择能力，但不产生对土地、工厂或基础设施的个人所有权。

### 3.3 透明的经济信息

决定不只依靠货币。库存、产能、劳动、能源、材料、时间、生态影响以及
资源的替代用途都应当可见。

### 3.4 自愿使用剩余

在满足基本保障后，一部分可支配剩余可以支持项目。项目依靠清晰的目标、
投入、风险和预期结果进行比较。资源分阶段提供，也可以停止。

### 3.5 反馈与审计

每一个重要决定都应留下可验证的链条：

> 需求 → 提案 → 规则 → 资源 → 行动 → 结果。

如果结果与承诺不同，就重新审查规则或项目。不能通过删除历史来隐藏错误。

## 四、需求如何连接到资源

过程如下：

1. 居民或群体记录需求。
2. 生产者和公共资产运营者公布可用资源及限制。
3. 协调环节把需求与库存、产能和已有承诺进行匹配。
4. 基本物资按照预先确定的准入权提供。
5. 项目公布选项、投入、期限和替代方案。
6. 居民和有权限的机构在可用实体资源范围内作出决定。
7. 执行者获得有限授权和分阶段资源。
8. 独立审查比较承诺结果和实际结果。

这不意味着任何请求都会自动得到满足，而是让拒绝原因、竞争方案和修订
决定的可能性变得可见。

## 五、决定层级

- **个人层面：** 使用个人份额并选择是否参与。
- **基本保障层面：** 食品、住房、医疗、教育和其他约定的基本服务。
- **项目层面：** 在额外项目及其阶段之间作选择。
- **战略层面：** 储备、重大基础设施和长期约束。
- **紧急层面：** 有自动到期和审计的临时措施。

决定影响的人越多、占用的未来资源越多，对论证、公开性和独立审查的要求
就应越高。

## 六、参与者角色

- **居民：** 表达需求、参与讨论和投票、验证结果并提出申诉。
- **生产团队：** 管理日常工作、公布产能并对交付负责。
- **协调环节：** 汇总需求、限制和承诺，但不获得对整个经济的无限控制。
- **专家：** 提供带有不确定性说明的计算和情景。
- **AI 助手：** 解释数据并发现矛盾，但不能投票或控制资源。
- **审计者：** 独立检查数据、决定和实体结果。
- **外部经济：** 继续用于贸易、比较，并检验内部制度没有变成目的本身。

## 七、本模型不是什么

本模型不承诺用一条规则消除短缺，不用投票取代专业管理，也不要求取消
所有市场。透明度本身不能消除利益冲突。提议只涉及可以在试点中检验的、
边界明确的公共资产和规则。

## 八、试点要检验什么

试点应回答五个问题：

1. 在没有隐性强制和质量下降的情况下，基本物资获得是否改善？
2. 剩余资源是否流向具有更清晰公共价值的项目？
3. 报告资源与实际资源之间的差距是否缩小？
4. 居民参与能否补充而不是瘫痪专业执行？
5. 审计和退出权能否停止失败的制度安排？

资源登记、电子投票和 AI 是检验这一框架的工具，而不是模型本身的目的。
