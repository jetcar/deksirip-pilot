# 试点技术架构

技术系统应当使资源配置可以审计，但不能把透明度变成全面监控。系统不
替居民作出政治决定，也不能依赖对单一运营者的信任。

## 一、系统层次

### 1. 身份与权利

- 受保护的身份和参与权证明；
- 将基本服务、社会分红和投票权分开确认；
- 分离公民身份、医疗数据和经济记录；
- 一人一票，不建立单一的公开生物识别数据库；
- 提供离线恢复和重新获得访问权限的程序。

### 2. 资源登记系统

登记系统记录实物，而不仅是货币：库存、批次、位置、生产能力、排产、
申请、预留、交付、实际消耗、劳动时间、能源、材料、生态损害以及每项
计算所使用的规则。

每次修改都应成为带签名的事件，历史不能被悄悄改写。系统不必默认使
用区块链；具有密码学哈希、多个独立副本和公开完整性校验的追加式分布
式日志可能已经足够。

### 3. 经济核算

每一种资源都应显示实物库存、已确认供应、储备、当前成本、竞争项目、
不确定性和估算范围。货币余额不能替代实物平衡。只有当人员、能源、材
料和产能都可见时，项目才算获得完整支持。

### 4. 电子投票

投票需要完整流程：提出方案、法律和资源审查、公开讨论、独立情景分析、
可验证投票、公布结果及其后果，以及按照预先确定的规则修改或取消。

敏感问题应当同时保证选择保密、选民可以验证自己的选票、总体结果可以
验证而不暴露个人选择。必须保留纸质和现场渠道。

### 5. 人工智能助手

人工智能可以解释计算、发现方案矛盾、运行情景分析、比较历史和地方数
据、显示可能的受益者和受损者、提出核查问题及相反论据，并提示数据质
量不足。

人工智能不能投票、修改登记、自行分配资源、隐藏不确定性，也不能把预
测说成事实。每个回答都应显示来源、数据日期、假设、不确定性范围和模
型版本。重要决定应比较多个独立模型，并由人作出结论。

### 6. 审计与公开验证

公开界面必须回答：

> 谁作出决定 → 使用了什么规则 → 使用了哪些数据 → 实物资源去了哪里。

审计人员应当获得可导出的数据、可重复的计算、独立节点、修改日志、抽
样检查、举报人保护，以及不依赖运营者私钥即可验证结果的方式。

## 二、紧急模式

启动前应当确定可量化的触发条件、临时授权者、允许的行动、授权期限、
自动终止机制和强制性的事后审计。恢复联网后，离线事件必须与共同日志
核对。

## 三、威胁模型

应当测试系统抵御库存数据造假、重复投票、胁迫选民、运营者密钥被盗、
问题或人工智能证据被操纵、个人数据泄露、网络和电力中断，以及数字登
记与实物库存不一致的能力。

核心原则是：数字透明度应当能够暴露错误，但不能让一个管理员悄悄改变
决定、资源或历史记录。
